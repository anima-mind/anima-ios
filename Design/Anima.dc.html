02b · Conversation mode · voice first, the mark is the face
Tap the mic (or the chip) in Chat: the conversation goes full-screen and the Breath mark becomes Anima's face. Listening: the wave follows your voice and the live transcript appears under it. Thinking: the wave stills, the glow pulses. Speaking: the wave moves with the voice while the caption streams. Controls: keyboard (back to text), the big button (send now / interrupt / talk again), mute. On exit both turns land in Chat marked "voice" and "spoken". When glasses are connected the same audio plays there and the HUD shows the matching card (§07).

07 · Glasses · Meta Ray-Ban Display, DAT SDK 0.9 vocabulary
The HUD is not a screen; it is a closed set of components the glasses runtime renders: FlexBox · Text (heading/body/meta × primary/secondary) · Icon (catalog) · Button (primary/secondary/outline) · ButtonGroup · Image. No colors, fonts, animation, streaming, gestures or inputs. Every view is a full swap, the system paints focus, and the system back gesture ends the session, so every non-root view carries its own Back button.
Deliverable per view is its component tree (right column); the dark panel is only an illustration of that tree. Click buttons to walk the state machine. All views pass the guide's checklist: root FlexBox, catalog icons only, ≤4 interactive, ≤3 buttons, reconstructible from app state, long content hands off to the phone.

Conversation on glass
Voice is the input and the output: the phone captures the glasses' mic, Anima answers out loud through the speakers, and the HUD shows the gist as a card. Turn detection is the phone's (pause to send); the SDK never sees audio, so each stage is a view swap: Listening → Heard (transcript, Again/Send) → Thinking → Reply (speaking, first sentence + one line, Reply/Proposal/On phone). A voice note ("remember that…") is recognized by the phone and lands as Heard · note → Kept for tonight, so what goes into memory is always shown before it is kept.
